# X11 (any EWMH window manager)

The `x11` adapter is built into the Fractile service. It uses EWMH
(window list, active window, `_NET_WORKAREA`, `_NET_FRAME_EXTENTS`,
`_NET_MOVERESIZE_WINDOW`, `_NET_WM_STATE`, desktops), ICCCM size hints
(`WM_NORMAL_HINTS`) and RandR for monitors. Global shortcuts use `XGrabKey` on
the root window. No extension, no privileges, no input injection.

## Tested

| Environment | Result | Evidence |
|---|---|---|
| GNOME Shell 46.0 / Mutter as X11 WM, nested in Xephyr 1600x1200, Pop!_OS 24.04 host | all checks pass | `e2e-x11.json`, `gui-x11.json`, `perf-x11.json` |
| Openbox on Xvfb inside clean Ubuntu 24.04 and Arch containers (package smoke: install, place, save, UI start, remove, reinstall, purge) | pass | `package-deb-ubuntu24.04.log`, `package-arch.log` |

**Not tested:** KWin on X11, Xfce/xfwm4, Cinnamon/Muffin, i3 and other tiling
WMs, multiple RandR monitors on X11 (multi-monitor was tested on GNOME Wayland
only), mixed DPI.

## Behaviour

- A placement is verified by reading the frame back from the WM. If the WM or
  the window's size hints change the result (for example size increments in
  terminals), the reported error is non-zero and the note says why.
- Windows that set `_NET_WM_WINDOW_TYPE` dock, desktop, splash, tooltip or
  notification, and Fractile's own windows, are never offered as targets.
- **Tiling WMs** (i3 and others) may ignore or override floating geometry.
  Fractile reports the observed geometry. It never changes WM settings.
- Without an EWMH window manager (`_NET_SUPPORTING_WM_CHECK` missing), Fractile
  still starts and lists monitors. Every window operation is reported
  unsupported, with that reason. This is checked live, so a WM that starts later
  is picked up.
